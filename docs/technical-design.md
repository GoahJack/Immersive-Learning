# 技术方案与数据设计

当前状态：**0.1.1 已建立应用工程、内部接口和 Windows x64 安装包；已完成部分自动化验证，人工系统验收尚未完成。** 本文所有技术决定均标记为【方案默认值】，用于区分需求来源，不代表用户逐项确认；实际验证以验收记录为准。需求来源见[产品文档](product.md)，术语见[项目说明](README.md)，验证见[验收清单](acceptance.md)。

## 1. 技术选型与影响范围

【方案默认值】采用 Electron + React + TypeScript，本地保存数据。主要比较如下：

| 路径 | 复杂度与成本 | 扩展性 | 风险与取舍 |
| --- | --- | --- | --- |
| Electron | 以 TypeScript 为主，首版窗口与托盘开发成本较低 | 便于扩展桌面窗口与前端交互 | 安装体积和内存占用较大，需限制渲染进程权限 |
| Tauri | 前端加 Rust 工具链，首版跨层调试成本较高 | 可扩展原生能力 | 安装体积通常更小，但增加工具链及原生集成工作 |

【方案默认值】推荐 Electron，优先降低托盘、独立提醒窗口和前端状态协作的实现成本。已锁定 Electron 45.3.1、React / React DOM 19.3.1、TypeScript 5.9.3、Vite 8.3.8 和 electron-builder 26.18.0；完整依赖与锁文件见项目根目录，真实运行命令见[运行说明](../README.md)。

【方案默认值】首版只面向个人 Windows 使用，数据保存在 Electron 用户数据目录；不需要账户、服务器或远程 API。开发阶段影响任务、提醒、计时、窗口及保存五个子系统，最容易受影响的是多窗口状态一致性和后台恢复；以状态机测试和 Windows 实机验收验证。

## 2. 进程与状态归属

【方案默认值】结构为：

```text
主窗口（React） ── 受限 preload 接口 ── 主进程
灵动岛（React） ── 受限 preload 接口 ── ├─ 任务与提醒调度
                                      ├─ 单会话计时状态机
托盘菜单 ──────────────────────────── ├─ 本地保存与恢复
                                      └─ 窗口及系统事件管理
```

【方案默认值】主进程是唯一状态来源和写入方，两个渲染窗口不自行计时、调度或保存。渲染进程只接收快照并提交操作；显示倒计时可本地刷新，但暂停、完成和累计时长以主进程为准。无需引入额外全局状态管理库，React 保存界面状态并订阅应用快照。

【方案默认值】主窗口关闭时阻止销毁并隐藏；彻底退出通过明确的退出流程处理。单实例运行，二次启动唤回已有应用。灵动岛采用透明无边框独立窗口，隐藏时不占任务栏、不拦截屏幕点击，展示时不主动抢焦点；托盘不依赖主窗口存活。

【方案默认值】启用上下文隔离、关闭渲染进程 Node 集成，仅暴露限定的 preload 方法。打开网页只接受经校验的 HTTP/HTTPS 链接；本地文件通过原生选择器选取，打开失败时提示并保留计时控制入口。任务文本作为文字展示，不执行或渲染其中的 HTML；材料不会嵌入具有本地权限的窗口。

## 3. 本地数据与最小接口

【方案默认值】采用带 `schemaVersion` 的单一 JSON 数据文件和最近一次有效备份；由主进程串行写入，通过同目录临时文件及替换完成保存。启动校验结构，损坏时尝试备份并明确告知；主文件和备份均不可用时保留原文件并提示恢复，不静默用空数据覆盖。

| 数据 | 最小内容 |
| --- | --- |
| 学习任务 | ID、名称、分类、材料类型及路径/链接/说明、目标、计划分钟数、提醒规则、最近进度、启用及归档状态、创建和更新时间 |
| 提醒实例 | ID、任务 ID、原计划时间、延后时间、状态（待处理/稍后/已开始/已跳过）；实例按任务 ID 与原计划时间唯一标识 |
| 学习会话 | ID、任务 ID、任务名及分类快照、关联提醒实例、目标时长、开始/结束时间、运行状态、累计专注时长、按本地日期分配的时长、结束进度、结束原因 |
| 应用设置 | 提醒声音、阶段提醒开关、开机启动、首次托盘关闭说明是否已展示 |

【方案默认值】时间点以标准时间戳保存，提醒规则保存本地日期、时间及星期；本地日期用于统计归属。任务编辑不修改历史会话快照，归档任务不删除学习记录；归档当前会话对应任务前，先要求结束该会话。首版不提供历史时长手动修改，避免统计和会话时长分离。

【方案默认值】以下为应用内部接口契约，不是 HTTP API，也不暴露通用文件或命令执行能力：

| 接口分组 | 输入与输出职责 |
| --- | --- |
| 读取与订阅 | 获取完整应用快照；订阅状态变更并返回取消订阅方法；快照包含任务、会话、提醒、统计、设置和保存状态 |
| 任务操作 | 创建、编辑、归档任务及设置提醒；返回保存结果或可展示的校验错误 |
| 会话操作 | 使用任务 ID、可选提醒实例 ID 和可选时长开始；按会话 ID 暂停、继续、延长、结束并提交可选进度 |
| 提醒操作 | 按实例 ID 稍后提醒；手动开始时只消费明确关联的实例，不隐式吞掉其他日期提醒 |
| 设置与窗口 | 更新设置、打开材料、显示主窗口、预览提醒、请求退出；只有主进程执行系统操作 |

【方案默认值】所有输入在主进程校验；业务操作返回成功状态或包含可展示信息的错误结果。成功保存后发布一致快照；失败时保留可重试状态并显示未保存提示。开始、结束和提醒消费按当前状态幂等处理，重复点击不创建重复数据。渲染窗口重建后重新读取快照。

## 4. 计时、调度与恢复

【方案默认值】会话状态为“运行中 → 暂停 → 运行中”，运行中或暂停均可结束；达到目标进入暂停并记录达到目标标记。全局最多一个未结束会话，窗口关闭不改变会话状态。继续 10 分钟使目标在当前累计时长基础上增加 10 分钟并恢复运行；普通继续不能越过已经达到的目标，须先延长。

【方案默认值】运行期间按单调经过时间累积专注时长，在暂停、结束、系统睡眠/锁屏和退出时保存，并每 5 秒保存检查点。跨本地午夜拆分时长归属。异常终止最多损失最后一次成功检查点之后的时间，健康写入时该区间不超过 5 秒；恢复后始终暂停，不累计离线时长。

【方案默认值】主进程监听睡眠、唤醒、锁屏和解锁事件，离开时暂停，回来后不自动继续。系统休眠和锁屏事件的实际可用性需 Windows 实机验证，不以窗口动画或前端定时器代替系统事件。

【方案默认值】调度器在运行时检查到期任务，并在启动、唤醒和本地时间变化后重新计算。每条重复规则只生成对应计划时间的唯一实例；展示过的实例不因轮询再次自动展示。延后只改变同一实例的再次提醒时间。

【方案默认值】应用恢复时：一次性未处理提醒加入待处理列表；每周任务保留最近一次错过的提醒，更早实例标记已跳过并继续计算下一次。多个待处理任务只展示一条汇总，学习中则保持在待处理列表。持久化实例状态，防止重启后重复消费。提醒展示和去重状态写入失败时提示错误，不声称处理成功。

【方案默认值】灵动岛展示时长、按钮、优先级及默认开关以[产品流程](product.md#4-学习与灵动岛流程)为准。系统日期时间影响任务安排，不直接影响会话累计时长。软件未运行时不使用系统计划任务单独唤起应用；开机启动为可选登录启动，不承诺关机或睡眠中准时提醒。

## 5. 实施与兼容约束

【方案默认值】首版无已有数据迁移任务，但必须保存格式版本；遇到未知的更高版本时提示不兼容，不覆盖文件。应用升级保留用户数据，安装与卸载行为需在打包阶段验证。

【方案默认值】按[验收清单](acceptance.md)逐阶段推进。已生成 Windows x64 NSIS 安装包和免安装应用目录；Windows 版本、架构和验证证据见验收记录，其他组合仍标为未验证。首版不上传学习内容或使用记录，排错依赖本地结果和可复现步骤。

【后续扩展】云端同步、自动内容识别、应用封锁等需要重新评估权限、数据模型和架构，不能直接视为当前接口已支持的能力。

## 6. 当前实现补充

【方案默认值】核心代码位于 `core/`，受限桌面桥接位于 `electron/`，共享类型与提醒时间计算位于 `shared/`，界面位于 `ui/`。主进程每秒刷新快照，健康写入时以约 4—5 秒间隔保存检查点；主窗口和灵动岛均不自行维护计时状态。

【方案默认值】任务保存、会话和提醒操作通过 `StudyAPI.command` 返回成功或可显示的错误；读取与订阅共享 `Snapshot`，文件选择单独走 `pickFile`，托盘结束操作通过受限 `onFinish` 通知打开进度表单。开机启动只允许在打包版开启，开发版提供明确提示。

【方案默认值】当前安装包未配置代码签名证书；已构建安装包，不等同于已执行安装、卸载或升级验收。开发/打包依赖审计存在 6 项中等风险通告，涉及 electron-builder 的 minimatch 依赖链，生产依赖无已知审计通告。TODO：跟进打包器上游修复并在升级后复核安装包；未直接套用审计建议的主版本降级或跨主版本覆盖，原因是需要保证已验证的打包兼容性。

## 7. 0.1.1 提醒显示修正

【方案默认值】原有渲染仅清空 body 背景，而 html 的 :root 背景仍可能显示。现对 html、body 和根容器统一透明，并显式指定原生透明背景；截图另使用保留透明通道方式导出。

【方案默认值】为临时提醒加入 eventId，每次 show 生成独立值；它不落入学习数据文件，不要求迁移 schemaVersion。发布状态时除比较内容，还校验原生窗口可见性；页面载入完成后重新发布。关闭原生提醒窗口改为收起，避免窗口销毁后后续提醒失效。收起延迟 220 毫秒，新提醒到来时取消延迟隐藏。

【方案默认值】未能在旧版测试中稳定复现用户的所有漏提醒条件，因此采用原生窗口、真实计时、连续相同通知及可见性恢复的回归验证，不将推测的单一原因视为唯一根因。新增测试见 tests/desktop/reminders.spec.ts。
