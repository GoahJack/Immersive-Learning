当前状态：**0.1.3 首版已实现；下表按已执行证据更新，尚未执行的人工或真实学习场景保留“尚未验证”。** 本文用例均为【方案默认值】，验证其中的用户需求或计划行为，不代表用户已逐条确认或测试已通过。

## 1. 执行约定

【方案默认值】阶段顺序为界面原型 → 学习闭环 → 桌面能力 → Windows 打包试用。每次重要实现前说明影响范围、潜在受影响模块和验证方式；上一阶段的问题明确处理后再扩展下一阶段。

【方案默认值】表中状态仅可按实际结果更新为通过或失败，并记录验证日期、应用版本、Windows 版本/架构和证据。未执行或环境不具备时保留“尚未验证”，不能用代码存在、测试计划或截图代替后台行为验证。

## 3. 第二阶段：学习闭环

【方案默认值】本阶段实现任务、会话、保存和统计。使用可控时钟验证时长和跨日规则，使用独立数据目录验证损坏恢复，不破坏真实学习记录。

| 编号 | 操作场景 | 预期结果 | 状态 |
| --- | --- | --- | --- |
| FLOW-01 | 新建、编辑、停用、归档任务；输入空名称、无效时长或无星期的重复规则 | 合法内容保存；无效内容明确提示；停用/归档停止后续提醒，保留历史 | 尚未验证 |
| FLOW-02 | 双击开始，并尝试开始另一任务 | 只有一个未结束会话，要求先继续或结束原会话 | 通过（逻辑 / 桌面自动化） |
| FLOW-03 | 运行 60 秒、暂停 30 秒、继续 60 秒 | 专注时长约 120 秒，暂停的 30 秒不进入统计 | 通过（逻辑 / 桌面自动化） |
| FLOW-04 | 点击“先学 5 分钟”，到期后选择继续 10 分钟 | 任务默认时长不变；到期暂停，继续后追加 10 分钟目标 | 通过（逻辑 / 桌面自动化） |
| FLOW-05 | 达到目标后长时间不操作 | 专注时长停在目标，仍可从主窗口处理结束或延长 | 通过（逻辑 / 桌面自动化） |
| FLOW-06 | 提前结束并填写进度；再次开始同一任务 | 会话保存为提前结束，实际时长计入统计；展示上次进度 | 通过（逻辑 / 桌面自动化） |
| FLOW-07 | 不填写进度直接结束；修改任务名称后查看历史 | 允许结束；原历史名称和分类快照不被改写 | 通过（逻辑 / 桌面自动化） |
| DATA-01 | 保存任务、提醒和记录后重启 | 数据保留；未结束会话恢复为暂停，离线时间不计入 | 通过（逻辑 / 桌面自动化） |
| DATA-02 | 健康写入时强制结束进程后重启 | 恢复最近成功检查点，不重复建会话；检查点间隔不超过 5 秒 | 尚未验证 |
| DATA-03 | 模拟写入失败、主文件损坏、主文件及备份均损坏 | 提示错误和恢复状态，允许重试；不静默覆盖原数据，不虚报已保存 | 尚未验证 |
| DATA-04 | 加载高于当前支持的格式版本 | 提示不兼容并保留文件，不尝试覆盖 | 通过（逻辑测试） |
| STAT-01 | 运行跨午夜及跨周会话，并插入暂停 | 时长归入正确本地日期与周，暂停不计入；进行中与结束后统计一致 | 尚未验证 |
| STAT-02 | 运行中修改系统日期时间 | 计时不因时钟跳变增加或扣除；提醒按新的本地时间重新计算 | 通过（逻辑测试） |
